This package contains what the manuscript's Data and code availability statement lists. The reproducible part runs with one command; the parts that need the mission recordings are separated and named.

## Contents

```
reproduce.sh                      one command: Tables 3-5, Figure 2, and the Figure 1 aggregates
code/
  wema_arms.py                    replay of the deployed bucket W-EMA estimator (reimplemented as specified in Section 3.3)
                                  over a collector event log, in two arms (retain / cleared at return) and two key
                                  variants (as deployed; --no-freq-key)
  make_figure.py                  regenerates Figure 2 from results/wema_all_cells.csv
  make_audit_figure.py            regenerates Figure 1 and its aggregates from the three archived mission recordings
  reproduce_tables.py             prints Tables 3, 4 and 5, the leave-one-mission-out range, the exact two-sided sign
                                  test, the descriptive bootstrap and the fidelity figure from the result files
results/
  wema_all_cells.csv              32 returning cells x 4 missions: cleared and retained early-return power MAE, their
                                  difference, and the production (logged) per-cell MAE  (deployed key)
  wema_freqkey_sensitivity.csv    the same cells for both key variants (freqkey / nofreq)
  wema_archive_cells.csv          the three archived missions only (subset of the above)
  e1_cap_medians.csv              Figure 1(a): median/P5/P95 of the reported core frequency per requested cap, per profile
  e3_phase_counts.csv             Figure 1(b): GPU-preferred and GPU-enabled action records per 1800-s phase
  e1_temporal_check.csv           per-profile temporal check: cap changes, holds >= 60 s, records >= 30 s after a change
  e1_temporal_check_holds.csv     the same check, one row per hold
  fig_retention.png               Figure 2 as regenerated by make_figure.py
manifests/
  portfolio_run_manifest.csv      every mission: date, source category, file digest, and its use in this and the two
                                  companion manuscripts (the inclusion rule of Section 5.1)
  MANIFEST.sha256                 every file in this package with size and SHA-256 digest
```

## Reproduce (no recordings needed)

```bash
bash reproduce.sh
```
Requires Python 3 with pandas, numpy and matplotlib. Expected output: Table 3 per-mission values; mean −0.1721 W,
leave-one-out −0.1842 to −0.1626 W, 4/4 missions, 32/32 cells, 76.2 %; the no-frequency variant −0.0789 W (68.2 %);
partition effect +0.110 W on the cleared arm and +0.017 W on the retained arm; fidelity 0.054 W; the Figure 1 aggregates
(reported frequency 1,479 MHz at every requested cap; the temporal check); `results/fig_retention.png` written.

## Definitions

A *cell* is one returning workload entry in one mission; its value is the mean absolute power-prediction error over the
first 75 control periods after that entry, on validity-flagged outcomes only. Predictions are issued before their
outcomes are revealed (prospective by construction). Four missions are the independent units; the bootstrap is
descriptive. The fidelity figure is the mean absolute difference between replay and production per-cell errors.
